# Decision and computation

For a task, freeze requirements, constraints and objective before ranking candidates. Retrieve only relevant cards, verify applicability and evidence, then apply hard constraints first. A missing hard-constraint input makes that candidate unresolved, not feasible. Compare feasible alternatives on defined criteria and units. When metrics or weights are absent, report Pareto trade-offs or qualitative comparison; no fabricated score. Resolve contradictory rules by explicit scope, edition, governing authority and task constraints; otherwise hold and report.

For each decision log: candidate IDs, measurements/inputs with units and origins, invoked rule IDs, applicability, PASS/FAIL/UNKNOWN/NOT_APPLICABLE outcomes, calculations, exceptions, remaining uncertainty, and rationale. Do not use textbook rules to override actual functional requirements or validated safety constraints.

For each deterministic calculation: explicit inputs and units; finite checks; domain checks; documented conversion; pure function where practical; no arbitrary eval or hidden defaults; hand-calculated reference values; invalid-input and boundary tests. Record formula evidence and script/test paths. If no executable formula is warranted, retain the index only. Distinguish unit tests, source validation, and physical validation. Do not claim industrial certification.
