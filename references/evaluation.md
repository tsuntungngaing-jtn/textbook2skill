# Evaluation and verification

Before declaring source verification, revisit the actual locator. Check terminology, signs, units, domain, missing exceptions, and whether a rule is direct or inferred. Record failed or partial evidence checks and unresolved conflicts. Check multiple evidence types when text and figure disagree. No claim of complete chapter review if only snippets were sampled.

Use three levels: (1) structural validation of pack; (2) semantic evidence review and deterministic calculation tests; (3) task-level evaluation with independent cases. A structural pass does not imply semantic pass; a semantic pass does not imply practical engineering validity.

For task-level evaluation, freeze input set, model/tool version, budget and rubric; compare target agent without pack versus with pack, optionally rules/scripts separately. Keep held-out cases and reference answers inaccessible during design. Track correctness, constraint violations, source citation accuracy, unsupported numerical claims, abstention quality, execution success, and cost/time. Report denominators, per-case outcome, limitations and observed differences, not causal improvement without controls. Never score a test as passed if it was not executed. Use synthetic original cases if real cases unavailable; label them synthetic and not independent field validation.
